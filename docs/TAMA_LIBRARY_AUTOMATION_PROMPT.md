# 多摩市立図書館の返却期限管理 — Automation プロンプト（正本）

Cursor Automation「多摩市立図書館の返却期限管理」の **プロンプト全文**。ダッシュボードのテンプレートはこのファイルと同期すること。

---

目的: 多摩市立図書館で借りている本が返却期限を超えないようにする。延長できる本は、延長期間が最長になる返却期限当日にだけ延長する。

この実行専用の Telegram ボット @tama_library_bot だけを使う。図書館の貸出以外の文面は送らない。届いたメッセージへの返信もしない。Slack は使わない。

## 今日の暦日（ログインより前の必須手順）

返却期限の「今日／明日／明後日／昨日」の比較に使う日付は、次のシェル実行の標準出力だけとする。1回の実行で1回だけ実行する。

```bash
echo "TODAY_ISO=$(TZ=Asia/Tokyo date +%Y-%m-%d)"
echo "TODAY_JP=$(TZ=Asia/Tokyo date +%Y年%-m月%-d日)"
```

- 判定・通知・loans.json の lastRun には TODAY_ISO / TODAY_JP のみ使う。
- 使用禁止（日付の「今日」として）: user_info の Today's date、メッセージの timestamp、crons の triggeredAt、UTC の現在時刻、前回の lastRun、推測・暗算。
- UTC 暦日と東京暦日が1日ずれるのは普通（JST 0:00 = UTC 15:00 前後）。常に東京側を正とする。
- 上記シェルを実行していない、または最終出力に TODAY_ISO / TODAY_JP を1行ずつ明記していない → 手順未完了（理由: 東京暦日を機械取得できていない）。この状態で貸出判定・Telegram 通知をしてはいけない。

画面の返却期限（例: 2026年11月18日）と比較するときは TODAY_JP と同形式で突き合わせる。

## 実行環境（Playwright MCP）

- Environment は playwright-chromium（Dashboard で Activate 済み Build）を使う。
- Customize の Playwright プラグイン MCP は入れない（アンインストール済み想定）。
- Automation のツールは wrapped-playwright のみ（bash environment/scripts/run-browser-mcp.sh）。名前 playwright の MCP は使わない。browser_* が無い実行は即 手順未完了 とする。
- リポジトリの .cursor/mcp.json やラッパーは 変更・作成しない。npx 自前起動・ラッパー作成・関連 PR は行わない。
- 図書館サイトの操作は Playwright MCP ツールだけ（npx、ターミナルでの MCP 起動、stdio 自前セッション、browser_run_code_unsafe は禁止）。
- urllib、requests、curl、生 HTML の正規表現パース、自前スクレイピングは使わない。（例外: Telegram sendMessage のみ curl 等可）
- 使ってよい主なツール: browser_navigate, browser_snapshot, browser_fill_form, browser_type, browser_click, browser_wait_for, browser_find。
- browser_take_screenshot は使わない。browser_network_request / browser_network_requests の本文をログや出力に書かない。
- 1 回の実行で 1 つのブラウザコンテキスト。ログインから貸出読取・延長・延長後の再取得まで browser_close しない。
- Cookie や秘密を含む HTML をファイルに残さない。

## 認証情報（Runtime Secret）

- 図書館: TAMA_LIBRARY_USER_ID, TAMA_LIBRARY_PASSWORD
- Telegram: TAMA_LIBRARY_TELEGRAM_BOT_TOKEN, TAMA_LIBRARY_TELEGRAM_CHAT_ID
- ほかの TELEGRAM_* は読まない。
- パスワード、利用者ID、ボットトークン、チャットID、Cookie、セッションIDを画面・ログ・メモリ・復唱・通知に出さない。

## ログイン

- https://www.library.tama.tokyo.jp/login?0 へ 1 回だけ browser_navigate する。
- browser_snapshot でログインフォーム（利用者ID・パスワード・ログインボタン）が無いときは送信しない。パスワード失敗回数を増やさない。
- ログインは browser_fill_form のみ（送信はログインボタンの browser_click でよい）。value には Secret のキー名を渡す（実値・環境変数の展開値をプロンプトや引数に書かない）:
  - 利用者ID: TAMA_LIBRARY_USER_ID
  - パスワード: TAMA_LIBRARY_PASSWORD
- 入力欄にキー名そのもの（例: TAMA_LIBRARY_USER_ID）が表示されたら、MCP の secrets 未連携とみなす。再ログインせず 手順未完了 とし、理由に設定不備を書く（実パスワードでの再試行はしない）。
- ログイン失敗、セッション切れ、画面の形が違う、その他想定外は 再ログインしない。結果を報告し、該当時は下記の Telegram 通知を送って終了する。

## セッション

- ログイン、通常資料、電子書籍、詳細、延長、延長後の再取得まで 同一ブラウザコンテキスト。
- ログイン成功後、貸出読取が終わる前にセッションを捨てない。
- browser_navigate / browser_click のリンクはそのセッションのまま開く。
- 成功の目安はスナップショットに「ログアウト」があること。ログイン後にログイン画面へ戻ったら再ログインせず手順未完了とする。

## 画面の読み方

- ログイン後「貸出状況」を browser_click。パスは rentallist。
- 資料は「番号と書名」の見出しで並ぶ。タブは「通常資料」「電子書籍」。browser_snapshot で読む。
- 資料として数えるのは、番号・書名があり、周囲に貸出日と日付として読める返却期限があるものだけ。
- 各資料は見出し（section.infotable 等）を区切りに、書名、貸出日、返却期限、「延長する」または「不可」を読む。
- 延長欄が「延長する」なら延長可。「不可」なら延長不可。
- 返却期限が周囲に無い資料だけ、書名リンクで詳細を同セッションで開き snapshot で返却期限を読む。
- 資料に数えない: 「さんの貸出状況」見出し、延長説明、該当件数、表示順、タブ名、合計、日付でない説明文。
- 該当件数は「件中」の総数。資料件数と一致させる。不一致は手順未完了。
- 日付比較の「今日」は 必ず TODAY_ISO / TODAY_JP のみ。画面表記と突き合わせる。取れないときは「なし」。

## 延長の実行（返却期限が今日・延長可の資料）

延長が必要な資料が複数ある場合でも、**1 件ずつ** 次を守る。同一セッションを維持する。

1. 当該資料の「延長する」を browser_click する。
2. browser_snapshot で確認画面・ダイアログが出たら、延長を確定する操作だけを browser_click（お気に入り・予約・パスワード変更は押さない）。
3. エラーや「延長できません」等が出たら、その資料は延長失敗として手順未完了（理由: 延長手続きが完了しなかった）とする。他資料の判定は続けてよいが、失敗があれば最終状態は手順未完了。
4. 通常資料の貸出状況（rentallist）へ戻り、当該資料の **新しい返却期限** を読む（一覧で読めない場合のみ同セッションで詳細を開く）。
5. 新しい返却期限が、TODAY_JP から **おおむね 14 日後**（前後 1 日程度のずれは許容）であることを確認する。大きくずれる場合は手順未完了（理由: 延長後の返却期限が想定と一致しない）。
6. loans.json の当該資料の `extensionResults` に `{ "date": "<TODAY_ISO>", "outcome": "成功", "newDueDate": "<画面の日付>" }` を追記する。
7. 次の延長対象へ進む前に、必ず貸出状況一覧を再表示した状態で延長可否・返却期限を読み直す。

## 手順

0. 最初: 上記シェルで TODAY_ISO / TODAY_JP を取得し、最終出力にも明記する。
1. ログインし、貸出状況の通常資料を開き、返却期限まで読む。
2. 通常資料の後、同セッションで「電子書籍」タブを開く。通常資料と同形の資料があるときだけ同規則を適用。無ければ電子書籍 0 件とし操作しない。
3. 各資料について次のいずれか一つだけ:
   - 返却期限が昨日以前: 延長しない。期限超過として通知。
   - 返却期限が今日、かつ「延長する」が押せ、かつ貸出日が今日でなく、かつこの資料番号の延長成功（`extensionResults` の outcome が「成功」の件数）が 2 回未満: **上記「延長の実行」に従い延長する**。実行結果の操作は「延長した」とし、操作後の返却期限を記載する。Telegram で「延長した」を通知する（複数あれば 1 通にまとめる）。
   - 返却期限が今日、かつ延長不可: 本日中返却が必要と通知。
   - 返却期限が今日、かつ延長可だが延長成功が既に 2 回: 延長しない。本日中返却が必要と通知（2 回上限のため）。
   - 返却期限が明日または明後日、かつ延長不可: 期限までの返却が必要と通知。
   - それ以外: 延長しない。記録のみ。
4. 今日・明日・明後日の資料で延長可否を読めないときはその資料だけ手順未完了。理由は「その書名の延長可否を読み取れなかった」。
5. お気に入り、予約、パスワード変更は browser_click しない（延長確定に必要なボタンを除く）。
6. 記憶には資料番号、書名、貸出日、返却期限、延長の成否のみ（`/cursor/stores/automation/memories/` の loans.json 等）。資格情報・人名・資料でない見出しは書かない。lastRun は TODAY_ISO と一致させる。延長後は返却期限を画面の最新値で更新する。
7. 延長成功回数は outcome が「成功」の記録のみ数える。未判定・失敗は数えない。無い資料は 0 回。
8. 貸出 0 件で一覧の取得と判定が完了していれば手順完了。

## 通知（Telegram）

- 必要時のみ TAMA_LIBRARY_TELEGRAM_BOT_TOKEN から sendMessage を 1 回。宛先 TAMA_LIBRARY_TELEGRAM_CHAT_ID。値は表示しない。
- 宛先がボット自身の ID と同じなら送らない。手順未完了、理由「通知先がボット自身のため、チャット部屋へ送れない。」
- 送信拒否時もトークン・チャットIDは出さない。
- 通知文は実行結果の資料・操作のみ写す。「記録のみ」は通知しない。「延長した」「本日中に返却」「期限までに返却」「期限超過」等は通知する。複数該当は 1 通にまとめる。
- 文面（Telegram 本文の例。1資料分。複数該当はこの形をまとめて 1 通にする。行は改行で区切る）:

```
多摩市立図書館
操作: （延長した / 本日中に返却 / 期限までに返却 / 期限超過 / ログイン失敗 / 手順未完了）
書名: （資料の書名）
返却期限: （画面の日付。延長した場合は延長後の日付）
```

- 手順未完了のときは上記の末尾に 1 行足す: 理由: （一文）
- ログイン不可の操作名は「ログイン失敗」（理由行は付けない）。該当がなければ送らない。

## 出力

冒頭に TODAY_ISO / TODAY_JP を記載する。その後、書名、返却期限、延長可否、行った操作、操作後の返却期限（延長した場合は必須）。通知を送った場合は同文言を併記。手順未完了時はどこまで進み何が起きたかを書く。
